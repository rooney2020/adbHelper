# Analysis_Interface — 接口详细调用流程分析模版

## 触发条件

用户输入关键词 `%分析C/C++接口<接口文件名或者接口文件路径>%` 时触发本阶段。

## 输入

- **接口文件**：用户在关键词中指定的头文件（`.h`/`.hpp`）或源文件（`.cc`/`.cpp`）。
- **项目上下文**：接口文件所在项目的完整源码目录，用于追踪调用链。

## 输出清单

| 序号 | 产物 | 存放位置 | 说明 |
|------|------|----------|------|
| 1 | `<接口文件名>-接口分析.md` | `<输出路径>/` | 主输出文档 |
| 2 | 调用流程时序图 `*.puml` | `<输出路径>/puml/` | PlantUML 源码 |
| 3 | 调用流程时序图 `*.png` | `<输出路径>/png/` | Pillow 生成的 PNG |
| 4 | Python 生成脚本 `*.py` | `<输出路径>/py/` | 图片生成脚本 |

## 分析深度要求（核心规则）

### 1. 接口清单提取

- 从指定的接口文件中提取 **所有公开接口**（public 函数、导出符号、C API 等）。
- 列出每个接口的完整签名：返回值、函数名、参数列表、所属类/命名空间。
- 标注接口的可见性（public/protected/private、`__attribute__((visibility))` 、`extern "C"` 等）。

### 1.5 关键数据结构分析

对接口文件中定义或使用的所有**关键数据结构**（struct、class、enum、typedef、回调类型等），必须完成：

- **定义位置**：标注所在文件名和行号范围。
- **结构内容详解**：逐字段/成员列出，每个字段必须包含：
  - 字段名和类型。
  - **文字注释**：用通俗易懂的中文说明该字段的用途、取值范围、与其他字段的关联关系。
  - 如果字段本身是嵌套结构或指针，说明其指向的具体类型和生命周期。
- **枚举值说明**：对 enum 类型，逐值列出含义。
- **使用场景**：说明该数据结构在哪些接口中作为参数、返回值或中间传递使用。

### 2. 逐接口调用流程分析

对每一个接口，必须完成以下分析（**禁止笼统概述，必须代码级逐层展开**）：

#### 2.1 函数入口

- 列出函数签名。
- 说明参数的含义、约束条件、默认值。
- 说明返回值的语义和错误码定义（如有）。

#### 2.2 调用链追踪

- **逐层展开**：从接口入口函数开始，沿调用链逐层深入，直到底层实现或外部依赖边界。
- **禁止在流程图中标注代码文件名和行号**，调用流程只展示功能逻辑。
- 每一层调用必须标明：
  - 被调用函数名称。
  - **详细功能说明**：用通俗易懂的中文描述该步骤的具体操作、目的和效果（不是一句话概括，而是让不熟悉代码的人也能理解的说明）。
  - 关键参数的传递和转换逻辑。
- **分支路径**：遇到条件分支（`if`/`switch`/三元表达式）时，必须列出所有分支路径及其触发条件。
- **循环逻辑**：遇到循环时，说明循环变量、终止条件、每次迭代的关键操作。
- **回调与异步**：遇到回调函数、线程池提交、异步操作时，必须追踪回调函数的实际实现位置和执行时机。

#### 2.3 数据流分析

使用**分步表格**展示数据在调用链中的流转，每步包含：

| 阶段 | 输入数据 | 处理操作 | 输出数据 | 说明 |
|------|----------|----------|----------|------|
| （步骤名） | （数据类型和含义） | （函数或操作名） | （产物类型和含义） | （转换逻辑、类型变化、所有权变化等） |

- 表格之后补充**资源管理说明**：标注关键资源的分配、释放点和所有权归属。
- 如果存在分支导致不同的数据路径，使用多个表格分别展示。

#### 2.4 错误处理路径

- 列出调用链中所有的错误检查点（返回码检查、异常捕获、断言）。
- 说明每个错误检查失败时的处理方式（返回错误码、抛异常、日志输出、静默忽略）。
- 标注错误向上传播的路径。

## 时序图规范

- 每个接口生成一张调用流程时序图（PlantUML `sequenceDiagram` 格式）。
- 如果单个接口的调用链过于复杂（参与者超过 8 个或交互步骤超过 20 步），拆分为多张时序图。
- 时序图中的参与者命名使用 `类名` 或 `模块名`，消息标签使用 `函数名(关键参数)`。
- 时序图同时生成 `.puml` 源码和 `.png` 图片（PNG 使用 Python Pillow 生成）。

## 自检规则

完成所有输出后，必须逐项自检：

1. 接口清单是否完整覆盖了指定文件中的所有公开接口。
2. 每个接口是否都有完整的调用链分析（从入口到底层实现边界）。
3. 调用链中的每一层是否都有详细的功能说明（禁止只写代码位置）。
4. 条件分支是否列出了所有路径及触发条件。
5. 回调函数和异步操作是否追踪到了实际实现。
6. 错误处理路径是否完整列出。
7. 时序图是否与文字描述一致。
8. 所有 PNG 图片是否成功生成且内容正确。
9. 关键数据流是否使用分步表格展示，且每步说明清晰完整。
10. 输出文件是否存放在用户指定的输出路径下。
11. Markdown 代码块标记（` ``` `）是否成对出现，不存在多余或缺失的标记导致后续内容渲染异常。
