# 安全漏洞检查清单

> 此文件由 SKILL.md 在完整模式下引用。对每个变更文件逐项检查。

## 攻击面映射（Step 2 增强）

分析每个变更文件时，先识别以下入口和敏感操作：

- 用户输入：请求参数、Header、Body、URL 组件、Intent extras
- 数据库操作：查询、写入、迁移
- 认证/授权检查：登录、Token 验证、权限判断
- 会话/状态操作：Session 读写、SharedPreferences、全局状态
- 外部调用：网络请求、文件系统操作、进程启动、IPC/Binder
- 加密操作：密钥生成、加解密、签名验证

## 安全检查项

逐项确认，跳过明显不适用项，标注无法确认的项：

| 检查项 | 关注点 |
|--------|--------|
| **注入** | SQL、命令注入、模板注入、Header 注入。拼接用户输入到查询/命令时触发。 |
| **XSS** | 动态输出未转义。WebView loadUrl/evaluateJavascript 传入用户数据时触发。 |
| **认证** | 受保护操作缺少认证检查。新增 API/Service 方法时检查是否暴露。 |
| **授权/IDOR** | 仅认证不代表授权。检查是否验证"当前用户有权访问此资源"。 |
| **CSRF** | 状态变更操作是否有 Token 保护（Web 场景）。 |
| **竞态条件** | 读-改-写无原子保护（TOCTOU）。多线程共享可变状态。 |
| **会话安全** | Session 固定、过期策略、Secure/HttpOnly 标志。 |
| **加密** | SecureRandom 而非 Random。AES-GCM 而非 ECB。密钥不硬编码、不写日志。 |
| **信息泄露** | 敏感数据出现在错误消息、日志、堆栈。时序侧信道。 |
| **DoS** | 无界循环/递归、缺失分页/限流、资源无上限分配。 |
| **业务逻辑** | 状态机非法转换、数值溢出、负数绕过、条件竞争窗口。 |

## 验证原则

发现潜在问题后，不要直接报告——先验证：

1. 检查是否已在其他代码路径中处理（如全局拦截器、基类方法）
2. 搜索是否有测试覆盖该场景
3. 读取周围 50 行上下文确认问题真实存在
4. 无法完全验证时，标注原因并降低置信度

## 输出格式

| # | 文件:行号 | 漏洞类型 | 严重度 | 问题描述 | 证据 | 修复建议 |
|---|-----------|----------|--------|----------|------|----------|
| 1 | path/File.java:L42 | 注入 | Critical | 用户输入直接拼入 SQL | `"SELECT * FROM " + input` | 使用 PreparedStatement |

严重度定义：
- **Critical** — 可远程利用，无需认证
- **High** — 需要认证或特定条件才能利用
- **Medium** — 影响有限或利用难度高
- **Low** — 理论风险，实际利用可能性极低
